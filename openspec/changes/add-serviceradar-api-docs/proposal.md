# Change: Add ServiceRadar API Docs To Developer Portal

## Why
The developer portal is supposed to be the public documentation surface for ServiceRadar, but the API reference is not yet sourced from the platform itself. Hand-authored API docs in the portal would drift from the real API contract and create two sources of truth.

ServiceRadar already has an OpenAPI path in `web-ng`. The portal should consume versioned OpenAPI artifacts generated by `serviceradar` and present them at stable developer-facing docs routes.

## What Changes
- Add portal requirements for ingesting ServiceRadar-generated OpenAPI documents rather than hand-authoring API reference pages locally.
- Define a versioned API-doc import pipeline that fetches OpenAPI artifacts from the canonical `serviceradar` repository or published raw artifact path.
- Add portal rendering requirements for interactive API reference pages, downloadable source artifacts, and cached refresh behavior.
- Document that ServiceRadar remains the source of truth for API contracts while the developer portal is the presentation layer.

## Impact
- Affected specs: `developer-portal`
- Affected code:
  - docs routing and navigation
  - OpenAPI ingestion and caching
  - developer portal docs UI and API reference rendering
  - deployment/runtime configuration for upstream OpenAPI source locations
